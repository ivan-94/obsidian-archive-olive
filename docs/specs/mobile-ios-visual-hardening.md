| 字段           | 值                                                 |

## 1. 目的

本规范用于修复 Archive Olive 在 iPhone 上的视觉可读性、表面层级和野兽派几何一致性问题，同时把已经通过验收的桌面端样式固化为不可回归基线。

本文是移动端整改的实现与验收合同。未同时通过移动端验收和桌面端回归门禁的变更不得提交发布。

## 2. 范围

### 2.1 本期范围

- iPhone 上的深色与浅色模式。
- 移动抽屉、右键/更多菜单、全局搜索、图谱设置、设置页、顶部操作栏和底部导航。
- 默认、悬停或触摸反馈、激活、选中、禁用和失焦状态。
- iOS 安全区、滚动、软键盘和不小于 44 × 44 CSS px 的触控区域。
- 同一补丁对 macOS 桌面端造成的视觉和交互回归。

### 2.2 非目标

- 不重新设计已经验收的桌面端。
- 不调整桌面端全局配色、排版、间距、边框或组件状态。
- 不把本期扩展为 Android 全量适配；可复用移动端规则不得主动破坏 Android。
- 不修复笔记内容引用的缺失图片等与主题无关的 vault 数据问题。
- 不在本规范阶段提交代码或发布版本。

## 3. 桌面端冻结与回归合同

桌面端当前表现是本期工作的不可变基线。移动端视觉优化不得以“统一全局规则”为理由改变桌面端。

### 3.1 选择器边界

- 新增或修改的移动端声明必须以 `body.is-mobile`、`.is-mobile` 为根；只有确有 iOS 平台差异时才追加 `.is-ios` 或 `.is-phone`。
- 新移动端 token 必须定义在 `.theme-dark.is-mobile`、`.theme-light.is-mobile` 或等价的移动端作用域中，建议使用 `--ao-mobile-*` 前缀。
- 禁止为了修复移动端直接修改无移动端限定的全局语义 token。
- 禁止依赖易变 DOM 层级、`:has()` 或 `!important`。
- 若确实需要修改全局规则，必须先提供桌面端修改前后截图、相关 computed-style 差异和必要性说明，并获得产品负责人明确批准；否则该实现不合格。

### 3.2 禁止回归的桌面端状态

以下已经验收的表现必须维持：

- macOS 深色与浅色模式。
- 窗口聚焦与失焦后的标题栏图标可见性。
- 顶部导航图标的默认、悬停和激活辨识度。
- 活动与非活动标签页的层级。
- 左右侧栏图标、底部 vault 切换器和侧栏滚动表现。
- 菜单默认、悬停、选中与禁用状态的文字辨识度。
- 表格表头默认与悬停状态。
- 文件列表当前项、工作区标题栏按钮及其失焦状态。
- 已修复的滚动条、菜单和图标问题。

### 3.3 桌面端基线门禁

实现开始前必须在固定的 Obsidian 版本、窗口尺寸、vault 和系统外观下保存桌面端基线截图。补丁候选必须在相同条件下复拍并比较：

- 非移动端选择器的 computed style 不得因本期变更发生意外变化。
- 基线覆盖的桌面端截图不得出现肉眼可见差异；任何预期差异都需要单独批准。
- 现有静态校验和发布校验必须继续通过。
- 桌面端回归失败会阻断移动端补丁，不得以“移动端已修复”为由豁免。

## 4. 审计结论与证据

审计通过 Safari Web Inspector 连接真实 iPhone 上的 Obsidian 完成。设备页面具有 `is-mobile is-ios is-phone theme-dark` 等运行时状态类。

### 4.1 MOB-001：深色移动端语义表面对比度不足（P0）

菜单、抽屉选择器和图谱设置输入框把浅沙色表面 `#b4aa8f` 与纸色文字 `#eee4c8` 组合使用。实测对比度约为 **1.82:1**，低于普通文字要求的 4.5:1。受影响菜单项并非禁用状态，实际 `opacity` 为 1。

截图证据来自本次真实 iPhone 审计，覆盖深色移动抽屉、菜单和图谱设置。原图包含真实 vault 名称、目录结构和笔记片段，依据 BRAT-008 隐私规则仅保留在本机未跟踪审计目录，不进入公开仓库。

期望：

- 深色默认表面使用深墨色或深橄榄表面，搭配纸色文字。
- 激活表面使用橄榄绿或青色实底，搭配 `#11110d` 墨色文字。
- 普通文字对比度不低于 4.5:1；大号文字和非文字控件不低于 3:1。
- 禁用状态可以减弱，但仍必须能识别标签与图标，且不得与普通状态混淆。

### 4.2 MOB-002：搜索结果表面半透明，正文穿透（P0）

全局搜索 `.prompt` 实测背景约为 `rgba(..., 0.9)`，`.prompt-results` 和 `.prompt-input` 为透明背景。搜索结果区域能看到笔记正文穿透，导致内容层级和文字辨识度下降。

截图证据记录了搜索结果表面下方可见的正文穿透。原图因包含真实笔记片段，仅保留在本机未跟踪审计目录。

期望：

- 搜索 prompt、输入区和结果区形成不透明的完整表面。
- 不依赖模糊或 backdrop filter 掩盖正文。
- 搜索结果滚动时背景保持稳定，不出现正文、图谱或其他工作区内容穿透。
- 输入框聚焦、失焦、空值和有值状态均保持清晰边界。

### 4.3 MOB-003：移动端圆角胶囊化破坏野兽派几何（P1）

审计发现菜单项、prompt、输入框、抽屉选择器、顶部按钮和底部导航存在 24–60 px 的大圆角；例如 44 × 44 顶部按钮使用 44 px 圆角，底部导航约使用 52 px 圆角。这与项目“矩形、硬边、仅语义圆形元素使用圆形”的设计规则冲突。

截图证据覆盖深色设置页胶囊容器、圆形工具按钮及浅色笔记页移动工具栏。原图因包含真实 vault 上下文，仅保留在本机未跟踪审计目录。

期望：

- 菜单、输入框、工具栏容器、抽屉选择器和 prompt 使用直角或项目定义的小幅硬边处理。
- 开关、图谱节点、状态点等具有明确语义的圆形元素可以保留圆形。
- 任何 iOS 平台几何例外必须在实现说明中逐项列出，不得以系统默认样式作为笼统例外。
- 视觉几何变化不得缩小触控热区。

### 4.4 MOB-004：移动工具栏动作层级过于平均（P1）

顶部和底部工具栏把大多数动作表现为同等强度的描边圆形按钮，内容区与导航区竞争注意力，激活状态也缺少明确层级。

期望：

- 默认动作采用安静的无框图标或低强度方形槽位。
- 当前视图、选中或按下状态使用青色/橄榄色实底、墨色图标和明确的硬边状态提示。
- 同一工具栏中最多只有当前动作使用最高强调层级。
- 图标及文字在默认、激活、按下、失焦和禁用状态下都可辨认。

## 5. 保持项

下列审计结果已经满足要求，修复时必须保留：

- 393 px 视口下 `clientWidth` 与 `scrollWidth` 一致，无页面级横向溢出。
- 笔记正文左右约 16 px 留白，正文约 16 px 字号、1.65 行高，阅读密度合理。
- 主要触控目标达到或接近 44 × 44 CSS px。
- 菜单滚动区保留 iOS 底部安全区，实测 `padding-bottom` 约 34 px。
- 当前文件使用 `#9aaa3a` 背景与 `#11110d` 文字，实测对比度约 7.38:1。
- 浅色笔记和浅色菜单可读；浅色菜单实测文字对比度约 15.36:1。
- 标签页切换器的卡片层级清晰。
- 图谱节点在正常缩放后可见；本次不把图谱画布对比度列为已确认阻断项。

## 6. 移动端设计要求

### 6.1 语义颜色

移动端实现应建立局部语义 token，而不是按组件重复硬编码：

| 语义           | 深色模式要求                             | 浅色模式要求                         |
| -------------- | ---------------------------------------- | ------------------------------------ |
| 默认工作表面   | 深墨色/深橄榄，纸色内容                  | 纸色/沙色，墨色内容                  |
| 次级或抬升表面 | 与背景有可见边界，文字对比度 ≥ 4.5:1     | 与背景有可见边界，文字对比度 ≥ 4.5:1 |
| 激活/选中      | 青色或橄榄色实底，墨色内容               | 青色或橄榄色实底，墨色内容           |
| 悬停/按下      | 不得使文字与背景趋同；须比默认状态更明确 | 同左                                 |
| 禁用           | 可减弱但标签仍可读，且需有非颜色线索     | 同左                                 |
| 边框/分隔      | 硬边、清晰，不以低对比度半透明阴影代替   | 同左                                 |

### 6.2 几何与层级

- 矩形组件默认 `border-radius: 0`；允许的小圆角必须有明确 token 和组件清单。
- 浮层使用实色背景、实线边框和硬偏移阴影，不使用毛玻璃。
- 视觉边框和触控热区分离：方形视觉不等于缩小可点击范围。
- 主要动作、当前动作和普通动作必须形成清晰的三级层级。
- 组件在窗口失焦或 WebView blur 后不得退回不可见的黑底黑图标/黑字状态。

### 6.3 行为与平台适配

- 保留原生滚动、惯性滚动、安全区 padding 和软键盘避让。
- 菜单、prompt 和设置面板在 393 × 852 视口内不得被裁切。
- 不允许新增页面级横向滚动条。
- 只覆盖视觉呈现，不改变 Obsidian 的菜单命令、手势、标签页或导航行为。

## 7. 组件级实现合同

### 7.1 移动菜单

- 默认、按下、选中、禁用和分组标题使用明确且独立的语义状态。
- 深色普通菜单项文字对比度 ≥ 4.5:1。
- 选中或按下后，文字和图标不得与背景同色。
- 菜单背景完全不透明。
- 保留底部安全区和纵向滚动。
- 去除非语义的胶囊圆角。

### 7.2 抽屉与 vault 选择器

- 折叠选择器不得使用 `#b4aa8f` + `#eee4c8` 的低对比组合。
- 默认与当前抽屉必须具有明显状态差异。
- vault 切换器、帮助和设置图标在深浅色及失焦状态下均可见。
- 保留不小于 44 px 的触控高度。

### 7.3 搜索 prompt

- prompt、输入区、结果区均使用不透明表面。
- 输入框焦点使用实线边框或硬阴影，不使用透明度作为唯一焦点线索。
- 结果项默认、选中和按下状态符合对比度门槛。
- 背后笔记正文不得透出。

### 7.4 设置与图谱设置

- 搜索输入、分组容器和选项行使用移动端语义表面。
- 选项标签、说明文字、输入值和 placeholder 均保持可辨认。
- 取消无语义胶囊容器，同时保留 44 px 以上触控目标。

### 7.5 顶部操作栏与底部导航

- 默认图标使用低强调、清晰可见的状态。
- 当前动作使用单一高强调实底状态。
- 按下反馈不得让图标消失。
- 安全区、手势区和系统状态栏不被遮挡。

## 8. 验收矩阵

### 8.1 iPhone 功能面

每个功能面均需在浅色和深色模式执行：

| 功能面       | 必测状态                                   |
| ------------ | ------------------------------------------ |
| 笔记页       | 默认、编辑、阅读、工具栏按下、失焦再恢复   |
| 左右抽屉     | 展开、折叠、当前项、滚动、vault 切换器     |
| 菜单         | 默认、按下、选中、禁用、长列表滚动、安全区 |
| 搜索         | 空查询、有结果、无结果、结果选中、键盘弹出 |
| 设置         | 分组、搜索、开关、返回、长列表滚动         |
| 图谱设置     | 搜索框、筛选项、折叠组、打开/关闭面板      |
| 标签页切换器 | 当前卡片、非当前卡片、关闭、新建           |

### 8.2 移动端通过条件

- AC-MOB-001：所有普通文字与背景的实测对比度 ≥ 4.5:1。
- AC-MOB-002：大号文字和关键非文字控件的实测对比度 ≥ 3:1。
- AC-MOB-003：深色菜单、抽屉选择器和图谱设置输入框不再出现审计中的低对比组合。
- AC-MOB-004：搜索 prompt 和结果区无任何底层正文穿透。
- AC-MOB-005：非语义胶囊圆角被移除或列入经批准的平台例外。
- AC-MOB-006：关键触控区域不小于 44 × 44 CSS px。
- AC-MOB-007：页面无横向溢出，浮层不被视口裁切。
- AC-MOB-008：菜单纵向滚动和 iOS 底部安全区继续正常工作。
- AC-MOB-009：默认、按下、激活、选中、禁用及失焦状态均有可辨识差异。
- AC-MOB-010：浅色模式当前可读性不因深色修复而下降。

### 8.3 桌面端通过条件

- AC-DESK-001：固定基线截图与候选截图无未批准的视觉差异。
- AC-DESK-002：标题栏和导航图标在聚焦、失焦、悬停和激活状态下保持可见。
- AC-DESK-003：活动与非活动标签页层级保持已验收表现。
- AC-DESK-004：菜单悬停/选中、表头悬停、文件当前项均无对比度回归。
- AC-DESK-005：侧栏图标和滚动条保持已验收表现。
- AC-DESK-006：所有移动端整改声明均通过选择器或移动端 token 隔离；未批准的全局样式 diff 为零。
- AC-DESK-007：现有验证脚本和发布验证通过。

## 9. 实施顺序

1. 固化桌面端基线截图、Obsidian 版本、视口和 computed-style 记录。
2. 新增移动端局部语义 token。
3. 修复深色菜单、抽屉和输入控件的表面/文字组合。
4. 把搜索 prompt 与结果区改为不透明表面。
5. 统一移动端硬边几何与工具栏动作层级。
6. 在真实 iPhone 上执行浅色/深色验收矩阵并保存截图证据。
7. 在桌面端执行完整回归矩阵，确认无未批准差异。
8. 由产品负责人验收；仅在收到明确指令后提交并发布 patch。

## 10. 验证与证据要求

- 真实 iPhone 是最终移动端视觉验收环境；Safari Web Inspector 用于记录 DOM 状态、computed style、尺寸与颜色。
- 每个缺陷至少保存修复前、修复后两张同场景截图。
- 对比度结论必须记录前景色、背景色和计算结果。
- 桌面端复拍必须与基线使用相同系统外观、Obsidian 版本、vault、窗口尺寸和缩放比例。
- 运行 `node scripts/validate.mjs --release` 及项目现有 CSS/格式校验。
- 审查 `git diff`，确保没有运行时设置、vault 数据或与本期无关的文件进入补丁。

## 11. 发布门禁

- 本规范本身不授权提交或发布；发布必须由产品负责人另行明确指令。
- `0.1.3` 的移动端候选已部署到 iCloud `test-vault` 并发布为 GitHub pre-release，供真实设备验收。
- 产品负责人在修复后真机矩阵尚未完成时明确要求发布 `0.1.3` patch；本次仅作为可回滚的 BRAT pre-release 例外，不把真机复验记录为已通过。
- 即使移动端验收通过，只要桌面端回归矩阵未通过，仍不得发布。

## 12. 风险与开放问题

- 是否允许底部 iOS 浮动导航保留有限圆角，需要在实现稿中给出视觉对比后由产品负责人决定；默认按硬边实现。
- 当前真实 iPhone 上未发现项目 `test-vault`，审计使用了设备现有 iCloud vault。正式验收前需决定是否同步专用 test vault。
- Android 未纳入本期完整验收矩阵；共享 `.is-mobile` 规则必须保持保守，iOS 专属差异使用 `.is-ios` 隔离。
- 审计控制台中的缺失 `leaf-*.png` 来自 vault 内容，不属于主题缺陷。
