## Publication checklist

- [ ] Three to five private-pilot environments are recorded.
- [ ] At least one pilot fresh-installs through BRAT.
- [ ] At least one pilot receives a changed `theme.css` through BRAT.
- [ ] Both Issue Forms render in a signed-in GitHub session and accept the intended dry run.
- [ ] No unresolved blocker issue remains.
- [ ] Known non-blocking issues are linked from the release or README.
- [ ] Owner completes the visual go/no-go.
- [ ] `node scripts/validate.mjs --release` passes on the approved commit.
- [ ] GitHub Actions is green on the approved commit.
- [ ] `git status --short` contains no release-owned change.
- [ ] The official community theme index is rechecked for the `Archive Olive` name.
- [ ] Tag `0.1.0` is absent before the release operation.
- [ ] The annotated `0.1.0` tag is created from the approved commit and pushed without rewriting history.
- [ ] `theme.css`, `manifest.json`, and `LICENSE` are attached from that tagged commit.
- [ ] The GitHub release is marked as a pre-release.

## Publication commands

Run only after every blocking checklist item passes and replace `<approved-commit>` with the reviewed full commit SHA:

```sh
git fetch origin
test "$(git rev-parse HEAD)" = "<approved-commit>"
git diff --quiet -- theme.css manifest.json LICENSE assets/screenshots/archive-olive-512x288.png docs/releases/0.1.0-beta-notes.md
git tag -a 0.1.0 <approved-commit> -m "Archive Olive 0.1.0 beta"
git push origin 0.1.0
gh release create 0.1.0 \
  theme.css \
  manifest.json \
  LICENSE \
  assets/screenshots/archive-olive-512x288.png \
  --repo ivan-94/obsidian-archive-olive \
  --verify-tag \
  --prerelease \
  --title "Archive Olive 0.1.0 Beta" \
  --notes-file docs/releases/0.1.0-beta-notes.md
```

After publication, read back the tag target, release flags, notes, and asset checksums. If publication fails after the tag is pushed, leave the tag intact, diagnose the release, and do not force-move the tag.

## Rollback

BRAT follows `main`, not the pre-release asset. Revert a faulty change with a new commit that intentionally changes `theme.css`, run the complete validation workflow, and verify the restored stylesheet through BRAT. Do not rewrite `main` or the published tag.
